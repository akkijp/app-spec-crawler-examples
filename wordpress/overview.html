Application overview

This is the administration area of a WordPress 7.1.4 site called "Acme Journal", used to write and publish posts and pages, moderate comments, and configure the site. The admin is organised by the left-hand menu: Dashboard, Posts, Media, Pages, Comments, Appearance, Plugins, Users, Tools and Settings. Content screens follow a list → edit pattern, and taxonomy screens (Categories, Tags) combine an add form with a list. Appearance and Plugins manage the theme and extensions, including installing from the WordPress.org directory. Tools holds import, export, Site Health and personal-data requests, and Settings holds site-wide options split across several forms. The site in this capture is a local demo with fictional content, viewed as an administrator.

Business domain and main entities

Publishing. The main entities are posts (with categories, tags, an author, a status such as Published, Draft or Pending, and comments), pages, media files, users with roles, themes and plugins. A post belongs to one author and to one or more categories; comments belong to a post and pass through moderation.

Intended users

Site administrators, who see every menu. WordPress also has Editor, Author, Contributor and Subscriber roles (the role names appear on the Users screens); what those roles see was not captured, because the crawl ran as an administrator only.

Authentication and permissions

The crawl used an already logged-in administrator session ("Howdy, demo" in the toolbar). The login screen itself is outside the crawled scope. Menus and buttons are probably hidden or reduced for lower roles (inferred; not captured).

Global navigation

A dark toolbar runs across the top with the site name, a search shortcut, a comments counter, a "New" menu and the account menu. The left-hand menu lists Dashboard (p001; Updates p002), Posts (p003; Categories p004; Tags p005), Media (p006; Add p007), Pages (p008), Comments (p009), Appearance (Themes p010; Editor p011; Fonts p012), Plugins (p013; Add Plugins p014), Users (p015; Add User p016; Profile p017), Tools (p018; Import p019; Export p020; Site Health p021; Erase Personal Data p022; Theme File Editor p023; Plugin File Editor p024) and Settings (General p025 through Privacy p032). "Collapse Menu" at the bottom narrows the menu to icons (inferred).

Shared UI and shared specs

Most screens have "Screen Options" and "Help" pull-down tabs at the top right. List screens share a pattern: status filters with counts, a "Bulk actions" selector with "Apply", a search box, sortable column headers and an item count. Settings screens are single forms ending in "Save Changes". The footer shows "Thank you for creating with WordPress." and the version.

Non-functional (as observed)

English UI. The menu can be collapsed. Tall screens (the plugin directory tabs and Credits) exceed 6,000 px and were captured in two parts. Screens such as Add Plugins and Add Themes load their content from WordPress.org.

Open questions

  • What do Editor, Author, Contributor and Subscriber accounts see? Only the administrator view was captured.
  • The "Add Post" screen (post-new.php) was deliberately not opened, because WordPress creates an auto-draft as soon as it loads. Its layout is probably the same as the Edit Post screen (p035).
  • What happens after any button is pressed (Save Changes, Apply, Install Now, Publish) was not observed; nothing was clicked or submitted.
  • The login screen and the public-facing site are outside the crawled scope.
