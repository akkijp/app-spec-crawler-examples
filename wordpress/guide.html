Acme Journal — WordPress admin System guide

This is the administration area of the WordPress 7.1.4 site "Acme Journal". The people who run the site use it to write and publish posts and pages, upload media, moderate reader comments, choose the site's look, add plugins, manage user accounts and set site-wide options. This guide describes the 50 screens that were captured, as seen by an administrator on a local demo site with fictional content.

What you can do with this system

The admin area covers six kinds of work, each with its own group in the left-hand menu.

Write and organise content

Create and edit blog posts and fixed pages in the block editor. Group posts with categories (hierarchical) and tags (flat). Upload images and files to the Media Library for use in content.

Moderate comments

Review comments left by readers, approve or unapprove them, reply, mark them as spam or move them to the trash. Comments waiting for moderation are highlighted and counted in a badge.

Shape the site's look

Choose the active theme, install more themes from the public directory, edit the site's design with the block-based "Site Editor", and manage font families.

Extend with plugins

Browse, search and install plugins from the WordPress Plugin Directory or upload a .zip file. Activate, deactivate or delete installed plugins and decide which ones update themselves.

Manage people and access

Add user accounts, assign roles (Administrator, Editor, Author, Contributor, Subscriber), send password resets, and let each user maintain their own profile.

Maintain and configure the site

Check updates and site health, import or export content, handle personal-data erasure requests, and set site-wide options for writing, reading, discussion, media, permalinks and privacy.

Who uses it and how

Administrators see every menu; what other roles see was not captured. The whole crawl was made with an already logged-in administrator account, so every screen in this guide reflects the administrator's view.

  • Administrator. Sees all ten menu groups: Dashboard, Posts, Media, Pages, Comments, Appearance, Plugins, Users, Tools and Settings. Installs themes and plugins, manages users, edits theme and plugin files, and changes settings.
  • Editor, Author, Contributor, Subscriber. These role names appear in the role filters and role dropdowns on the Users screens. Menus and actions are probably hidden or reduced for these roles (inferred). New accounts default to "Subscriber", the least-privileged role.
  • Every logged-in user. The "Profile" screen always shows the account of the person who is logged in and is probably available to every role (inferred). A user cannot change their own username or, on that screen, their own role.

Common elements for all users: a dark toolbar across the top with the site name, a search shortcut, a comments counter, a "New" menu and the account menu. Most screens have "Screen Options" and "Help" tabs at the top right. "Collapse Menu" at the bottom of the left-hand menu probably narrows it to icons (inferred).

Main workflows

Four routine tasks show how the screens connect: editing a post, moderating a comment, adding a user, and installing a plugin. No button was pressed during the capture, so the result of each final step is described as the screens suggest it, not as observed.

Edit and save a post

  1. Open Posts and narrow the list with a status view ("All", "Mine", "Published", "Draft", "Pending"), the "Search Posts" box, or the date and category filters.
  2. Click a post title to open it in Edit Post. On a first visit, close the "Welcome to the editor" dialog or step through it with "Next".
  3. Edit the title and body in the canvas, then adjust "Status", "Publish", "Slug", "Author", "Categories" and "Tags" in the "Post" tab of the sidebar.
  4. Press "Save". The button looks dimmed until there are unsaved changes (inferred).
  5. If a needed category or tag does not exist yet, create it first on Categories or Tags.

Moderate a reader comment

  1. Notice the badge next to "Comments" in the menu, or the "[Pending]" flag in "Recent Comments" on the Dashboard.
  2. Open Comments. The pending comment is shown with a pale yellow background and a red left border.
  3. Hover the row and choose "Approve", "Reply", "Spam" or "Trash" (the row actions appear to be revealed on hover, inferred).
  4. For several comments, tick their checkboxes, pick "Approve", "Unapprove", "Mark as spam" or "Move to Trash" in "Bulk actions" and press "Apply".
  5. To change when comments are held for moderation, go to Discussion Settings.

Give a new person access

  1. Open Users to check which accounts and roles already exist.
  2. Press "Add User" to open Add User.
  3. Fill in "Username (required)" and "Email (required)", set the password, decide whether to keep "Send the new user an email about their account" ticked, and choose a "Role" (default "Subscriber").
  4. Press "Add User". This probably creates the account and returns to the user list (inferred).
  5. To change the role later, open the account in Edit User or use "Change role to…" on the Users list.

Install and activate a plugin

  1. Open Plugins and press "Add Plugin".
  2. On Add Plugins, browse the "Featured" cards, switch to Popular or Recommended, or type into "Search Plugins" to reach Search results.
  3. Click "More Details" to read the Plugin Information window: version, requirements, compatibility, ratings and reviews.
  4. Press "Install Now". The button probably turns into "Activate" once the plugin is installed (inferred). Plugins that are not in the directory can be installed from a .zip file on Add Plugins — Upload.
  5. Back on Plugins, activate the plugin and optionally press "Enable auto-updates".

Feature by feature

Each category below shows a representative screen and lists what can be done there.

Dashboard and updates

  • See content counts ("7 Published posts", "5 Published pages", "2 Comments", "1 Comment in moderation") as links into the list screens.
  • Read the five most recently published posts and the latest comments; pending comments are highlighted and offer inline moderation actions (inferred).
  • Jot down a draft in "Quick Draft" with a "Title" and "Content" and press "Save Draft".
  • Follow shortcuts in the welcome panel: "Add a new page", "Open site editor", "Edit styles"; hide the panel with "Dismiss".
  • On Updates, see "Current version: 7.1.4", the last check time, "Check again.", "Re-install version 7.1.4", and whether plugins and themes are up to date. Automatic updates for every new WordPress version are enabled on this site.

Posts, categories and tags

  • List posts with columns "Title", "Author", "Categories", "Tags", a comments column and "Date"; filter by status, month and category; sort by title, comment count and date.
  • Act on rows with "Edit", "Quick Edit", "Trash" and "View" ("Preview" for drafts and pending posts), or use "Bulk edit" and "Move to Trash".
  • Edit a post's title and body with blocks; set "Status", "Publish" date, "Slug", "Author", "Template", "Discussion", "Format", a featured image, an excerpt, categories and tags; "Move to trash".
  • On Categories, add a category with "Name", "Slug", "Parent Category" and "Description"; on Edit Category, rename it, change its parent, or "Delete" it.
  • On Tags, add a tag with "Name", "Slug" and "Description" (no parent); on Edit Tag, rename or delete it.
  • Convert between categories and tags through the "category to tag converter" and "tag to category converter" links.

Media

  • Browse the Media Library in grid or list view; filter by type ("Images", "Audio", "Video", "Documents", "Spreadsheets", "Archives", "Unattached", "Mine") and by month; search with "Search media". The library was empty in the capture.
  • Upload files by drag-and-drop or "Select Files"; fall back to the "browser uploader" if needed.
  • Choose the generated image sizes and the upload folder structure on Media Settings.

Pages

  • List pages with "Title", "Author", a comments column and "Date"; filter by status ("All", "Mine", "Published", "Draft") and month; sort by title, comment count and date.
  • Use "Edit", "Quick Edit", "Trash" and "View" / "Preview" per row, or "Bulk edit" and "Move to Trash".
  • Press "Add Page" to create a new page. The page designated as the privacy policy is labelled "Privacy Policy Page" in the list.

Comments

  • Filter by "All", "Mine", "Pending", "Approved", "Spam" and "Trash"; search with "Search Comments"; filter by comment type.
  • Per comment: "Approve" or "Unapprove", "Reply", "Quick Edit", "Edit", "Spam", "Trash" (revealed on hover, inferred).
  • In bulk: "Unapprove", "Approve", "Mark as spam", "Move to Trash".
  • See for each comment the author, the post it answers ("In response to") with a "View Post" link and that post's comment counts, and "Submitted on".

Appearance

  • See which theme is active, "Customize" it, and "Activate" or "Live Preview" another installed theme (controls revealed on hover, inferred).
  • On Add Themes, browse the directory by "Popular", "Latest", "Block Themes" and "Favorites", search, use "Feature Filter", "Install" and "Preview", or "Upload Theme" from a ZIP file. Installed themes carry an "Installed" banner.
  • In the Site Editor, edit site identity, global styles, page layouts, navigation menus, patterns and templates; a "Saved" indicator shows there are no unsaved changes.
  • On Fonts, review the families under "THEME" ("1 of 1 active"), switch variants on or off and press "Update", or add fonts through the "Upload" and "Install Fonts" tabs.

Plugins

  • List installed plugins with description, version and author; filter by "All", "Inactive" and "Auto-updates Disabled"; search installed plugins.
  • Per plugin: "Activate", "Delete", "Enable auto-updates", "View details". In bulk: "Activate", "Deactivate", "Update", "Delete", "Enable Auto-updates", "Disable Auto-updates".
  • Find plugins by "Featured", "Popular" (74,726 items over 2,076 pages), "Recommended", "Favorites" (by WordPress.org username) or a search by "Keyword", "Author" or "Tag".
  • Each card shows rating, "Last Updated", active installations and either "Compatible with your version of WordPress" or "Untested with your version of WordPress".
  • Install from a .zip file with "Upload Plugin"; the same form installs or updates a plugin.

Users

  • List users with "Username", "Name", "Email", "Role" and "Posts"; filter by role; sort by username or email.
  • Per user: "Edit", "Delete", "View", "Send password reset" (only "Edit" and "View" for the logged-in user). In bulk: "Delete", "Send password reset", and "Change role to…".
  • Create an account on Add User with a generated or typed password, a notification email and a role.
  • On Edit User, change another user's "Role", details and password, or "Send Reset Link", then "Update User".
  • On Profile, set personal options ("Administration Color Scheme", "Language", "Toolbar" and more), name, contact info, biography, a new password, and "Log Out Everywhere Else"; press "Update Profile".

Tools

  • The Tools landing screen holds one card, "Categories and Tags Converter", pointing to Import.
  • On Import, pick one of seven importers ("Blogger", "Categories and Tags Converter", "LiveJournal", "Movable Type and TypePad", "RSS", "Tumblr", "WordPress"), each with "Install Now | Details".
  • Export content as a WXR (WordPress eXtended RSS) XML file for backup or migration.
  • Check Site Health — Status for issues grouped by severity, each labelled "Performance" or "Security", and Site Health — Info for 10 collapsible configuration sections and "Copy site info to clipboard".
  • On Erase Personal Data, register a request by "Username or email address", optionally send a confirmation email, and track requests by "Requester", "Status", "Requested" and "Next steps".
  • Edit theme and plugin source files directly in the Theme File Editor and Plugin File Editor after acknowledging the "Heads up!" warning; save with "Update File".

Settings

  • General: "Site Title", "Tagline", site icon, "WordPress Address (URL)", "Site Address (URL)", "Administration Email Address", "Anyone can register", "New User Default Role", "Site Language", "Timezone", "Date Format", "Time Format", "Week Starts On".
  • Connectors: install or activate shared credentials for "Akismet Anti-spam", "Anthropic", "Google" and "OpenAI"; "Install the AI plugin".
  • Writing: "Default Post Category", "Default Post Format", "Post via email" mailbox settings, "Default Mail Category", "Update Services".
  • Reading: homepage mode ("Your latest posts" or "A static page (select below)"), posts per archive page and per feed, "Full text" or "Excerpt" in feeds, "Discourage search engines from indexing this site".
  • Discussion: who may comment, threading, pagination, "Email me whenever" notifications, approval rules, "Comment Moderation" and "Disallowed Comment Keys" word lists, avatars.
  • Media: "Thumbnail size", "Medium size", "Large size", and "Organize my uploads into month- and year-based folders".
  • Permalinks: "Plain", "Day and name", "Month and name", "Numeric", "Post name" or "Custom Structure" built from tags such as "%postname%"; optional "Category base" and "Tag base".
  • Privacy: "Create" a new privacy policy page or "Use This Page" for an existing one; the Policy Guide tab supplies a template and suggested wording.

About WordPress

  • Read what changed in the installed version, the "Maintenance and Security Releases" list, and links to release notes.
  • Browse the static Get Involved, Credits, Freedoms and Privacy pages. They describe the WordPress software and community, not the Acme Journal site, and have no function for running it.

Terms

These words have a specific meaning in this system.

Post
A dated blog entry with one author, one or more categories, optional tags, a status and comments. Listed on "Posts".
Page
A fixed, undated piece of content such as "About" or "Contact". Pages have no categories or tags.
Category
A hierarchical label for posts; a category can have a "Parent Category". "Uncategorized" is the default and cannot be deleted.
Tag
A flat keyword label for posts, with no hierarchy.
Slug
The part of a web address that identifies a post, page, category or tag, for example "meet-the-team".
Published / Draft / Pending
Post and page statuses. Published items are public; a Draft is unfinished; Pending means waiting for review.
Pending comment / Moderation
A comment that is held until someone approves it. Pending comments are counted in the badge next to "Comments".
Quick Edit / Bulk edit
Row and bulk actions on list screens for changing fields without opening the full editor. Their fields were not captured.
Block editor
The editing interface used on "Edit Post" and in the "Site Editor", where content is built from blocks.
Theme
The package that controls the public site's look. Exactly one theme is active; "Twenty Twenty-Five" is active here.
Block theme
A theme whose design is edited with the block-based "Site Editor" (probably the case here, inferred).
Plugin
An extension that adds features. Plugins are installed, then activated separately; "Akismet Anti-spam: Spam Protection" and "Hello Dolly" are installed but inactive.
Role
A user's permission level: Administrator, Editor, Author, Contributor or Subscriber.
Featured image / Excerpt
An image and a short summary attached to a post in the "Post" tab of the editor.
Permalink
The permanent public address pattern of posts and archives, chosen on "Permalink Settings".
WXR
"WordPress eXtended RSS", the XML file format produced by "Export" and read by the "WordPress" importer.
Site Health
Automatic checks of the installation, grouped into critical issues, recommended improvements and passed tests, with an "Info" tab of configuration data.
Connector
A stored API key or credential for an external service, shared across plugins, on the "Connectors" settings screen.
Gravatar
An external service that supplies profile pictures by email address; the "Profile" screen links to it.
Application Passwords
A feature for giving applications their own login credentials. It requires HTTPS and is unavailable on this site.
Update Services
Addresses notified when a post is published, listed on "Writing Settings".

Things to confirm

These points were not observable in the read-only capture and should be checked with the site's users or developers.

  • Other roles. What Editor, Author, Contributor and Subscriber accounts see; only the administrator view was captured. Can non-administrators open Users, Tools or Settings? Do authors see all media files or only their own?
  • Results of actions. Nothing was clicked or submitted, so what happens after "Save Changes", "Apply", "Install Now", "Publish", "Save", "Update File", "Add User" or "Send Request" is unknown.
  • Confirmation dialogs. Whether "Trash", "Delete", "Spam", "Activate", "Move to trash" and "Re-install version 7.1.4" ask for confirmation before acting.
  • Add Post. The "Add Post" screen was deliberately not opened because WordPress creates an auto-draft on load. Its layout is probably the same as "Edit Post".
  • Hidden fields. The "Password" row on "Add User" and the "New Password" row on "Profile" and "Edit User" were not visible in the captures.
  • Quick Edit and Bulk edit. Which fields they expose on Posts, Pages, Categories, Tags and Comments.
  • Pagination. How many rows the Posts, Pages and Users lists show before pagination appears, and whether Add Themes loads more cards on scroll.
  • Comments. Whether replying to a pending comment also approves it, who receives the "Email me whenever" messages, what a "note" is in "Anyone posts a note", and whether moderation changes affect comments already waiting.
  • Pages. Why four published pages have no author, and whether "Privacy Policy Draft" (published) is intentionally separate from the draft "Privacy Policy" page. Why "Privacy Policy" is offered on Privacy Settings but not in the Reading Settings page selects.
  • Media. Which file types are accepted, what the grid and the attachment details look like once files exist, and whether existing images are regenerated when sizes change.
  • Appearance. Why the Site Editor canvas is blank in the capture, whether theme-supplied fonts can be deleted, whether "Install Fonts" contacts an external service, and where an inactive theme is deleted from.
  • Plugins. What the Add Plugins screens show when WordPress.org cannot be reached, why the recommended list equals the featured list, whether the installed-plugin list is sent to WordPress.org, and the maximum upload size for plugin .zip files.
  • Users. What happens to a user's posts when the user is deleted, what "— No role for this site —" does, where the display name shown on "Edit User" is stored, and whether the notification email contains the password or a link.
  • Tools. What each Site Health issue shows when expanded and whether copied site info masks private values; which statuses and "Next steps" an erasure request goes through; whether the file editors are disabled in production.
  • Settings. Whether posting by email is actually active, how often the mailbox is checked, whether the permalink change creates redirects, and how stored connector API keys are protected.
  • Out of scope. The login screen and the public-facing site were not captured. Three addresses that duplicated other screens are not repeated in this guide.
