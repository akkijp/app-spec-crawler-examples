About this screen

Purpose

Gives the site administrator one place to see what in the configuration needs attention, ordered by urgency, before users notice a performance or security problem. It is the diagnosis half of Site Health; the raw configuration data is on p046 Site Health — Info.

Shown when

Shown from Tools › Site Health. The capture shows the finished state: the indicator reads "Should be improved" and both issue groups are listed. The checks probably run after the page loads, so a loading state may appear briefly first (not captured).

Who uses it and how

The site administrator opens it after installing or updating something, or when the "Site Health" menu item shows a count badge, expands each issue to read the explanation, and fixes the cause elsewhere in the admin.

Main features

  • Automatic health checks run on page load
  • Issues grouped by severity: critical, recommended, passed
  • Category label ("Performance" / "Security") on each issue
  • Expandable rows with details for each issue
  • Tab switch between "Status" and "Info"

Usage flow

  1. Open "Tools" → "Site Health".
  2. Wait until the overall result (here "Should be improved") is shown under the title.
  3. Read the critical issues first and expand each one for details.
  4. Go through the recommended improvements, then fix the causes on the relevant screens (plugins, themes, scheduled tasks).
  5. Open "Info" when the raw configuration values are needed.

Variants and business rules

States and variants

Finished state (captured): the indicator shows the overall verdict "Should be improved" and the two issue groups are listed. A loading state before the checks finish probably exists but was not captured. The expanded state of the issue rows and of "Passed tests" was not captured. A site with no issues would presumably show no critical or recommended groups.

Business rules and constraints

Critical issues are meant to be resolved before recommended ones, as the on-screen explanations say. The number in the menu badge appears to follow the number of outstanding issues, but the exact rule is not visible.

Open questions

  • What does each issue show when expanded (text, links to fix it)?
  • Which checks are listed under "Passed tests", and how many are there?
