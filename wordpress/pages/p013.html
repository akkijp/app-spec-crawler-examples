About this screen

Purpose

The control point for what extra code runs on the site: an administrator turns plugins on and off, removes them and decides which ones update themselves. It is the first item ("Installed Plugins") under "Plugins" in the side menu and the starting point for p014 Add Plugins.

Shown when

Opened from "Plugins" > "Installed Plugins" in the side menu. Shown to the logged-in user "demo" (an Administrator); whether lower roles can open it was not captured.

Who uses it and how

A site administrator checking what is installed, activating a plugin after installing it, or cleaning up unused ones. Typical use is occasional, after an install or before an update.

Main features

  • List installed plugins with description, version and author
  • Filter by status ("All", "Inactive", "Auto-updates Disabled")
  • Search installed plugins
  • Activate or delete a single plugin from its row
  • Bulk activate, deactivate, update, delete, and switch auto-updates
  • Open plugin details ("View details")

Usage flow

  1. Open "Plugins" from the side menu and review what is installed.
  2. Click "Activate" under a plugin to turn it on, or "Delete" to remove it.
  3. For several plugins, tick their checkboxes, choose an action in "Bulk actions" and press "Apply".
  4. Click "Enable auto-updates" for plugins that should update themselves.
  5. Click "Add Plugin" to install something new.

Variants and business rules

States and variants

Captured with two inactive plugins and no active one. An "Active" filter, a "Deactivate" row link, update notices and the empty list were not seen.

Business rules and constraints

A plugin must probably be inactive before it can be deleted, since "Delete" is shown only next to "Activate". The counts in the filter links reflect the current plugin states.

Open questions

  • Does "Delete" ask for confirmation before removing the plugin files?
  • Where does "Activate" land when the plugin has its own setup screen (for example Akismet's API key)?
