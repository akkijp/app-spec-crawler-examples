Erase Personal Data

A tool for registering and tracking requests to delete or anonymize the personal data the site holds about one person. It has a short request form on top and a list of requests below, which is empty on this demo site.

About this screen

Purpose

Supports compliance with privacy laws: when someone asks for their data to be removed, the site owner records the request here and follows it through to erasure. The on-screen text says it works "by deleting or anonymizing known data for a given user".

Shown when

Shown when "Tools" → "Erase Personal Data" is opened. With no requests the list shows "No items found." and the filter reads "All (0)". Probably limited to administrators.

Who uses it and how

The site owner or administrator, on receiving an erasure request, enters the person's username or email address, sends the request, and later comes back to the list to carry out the next step.

Main features

  • Register an erasure request by username or email address
  • Optional confirmation email to the person concerned
  • Request list with status and next step per request
  • Status filter with counts above the list
  • Sorting by requester and by request date
  • "Screen Options" for adjusting the list view

Usage flow

  1. Open "Tools" → "Erase Personal Data".
  2. Enter the person's username or email address.
  3. Leave the confirmation email checkbox ticked, or untick it if the request was already confirmed another way.
  4. Press "Send Request"; the request probably appears in the list below.
  5. Once the person has confirmed, return to the list and carry out the action shown under "Next steps".

Variants and business rules

States and variants

Only the empty state was captured. With requests present the list would show one row per request, more status filters, and probably bulk actions and per-row actions. Error messages for an unknown user or invalid address were not captured.

Business rules and constraints

Erasure is a two-stage process as far as the screen shows: a request is recorded first and acted on later, with the person's confirmation by email as the default. The introduction says data is deleted or anonymized, so some records are probably kept in anonymized form.

Open questions

  • Which status values exist and what does "Next steps" offer at each one?
  • What happens when the username or email address does not match any known person?
  • Which data is deleted and which is only anonymized?
  • Are bulk actions available once requests exist?
